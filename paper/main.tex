\title{Testing Delivery-Conformance Checks in MP-SPDZ:\\
A Pre-Registered Mutation Case Study}

\begin{abstract}
Continuous integration turns a security property into a green check, and a green check
is easily mistaken for a guarantee. We report a reproducible \emph{testing} case study of
that green check for one secure multi-party computation (MPC) application: the
deterministic-query fragment of the knowledge-threshold belief computation of Mardziel,
Hicks, Katz and Srivatsa (PLAS 2012), implemented on MP-SPDZ with three-party replicated
secret sharing. The subject has no ground-truth oracle, so we build a separately
implemented plaintext \emph{pseudo-oracle}, an \emph{anti-echo} interface that keeps
expected outputs out of the system under test, a strict runtime transcript oracle, and
recomputed, hash-bound test evidence; a bounded 228-case adversarial matrix and five
committed executable negative controls exercise a static \emph{delivery-conformance}
checker that inspects compiled assembly. We evaluate that checker's adequacy by
\emph{mutation analysis} whose operator space is a restricted, enumerated set of
application-level transformations, and---because an adaptive mutation sequence adapts to
the tool it hardens---we add a \emph{pre-registered, temporally held-out} mutation study:
22 mutants with predictions committed \emph{before} execution and run once against the
frozen checker. Freezing the checker and pre-registering the corpus \emph{reduces}
post-hoc adaptation; the study remains white-box and same-project, not an independent
red-team. The decisive result is a \emph{surviving}, source-realizable mutant, H-R2: a
multiset-preserving mis-delivery that the structural checker accepts and that a
downstream transcript oracle catches, for that concrete labelled mutant. We report
exact-strength results and honest mutant accounting (killed / survived / stillborn), and
we report no aggregate mutation score for manifest-level probes whose source
realizability is unproven. The artifact reproduces from a fresh checkout at the pinned
backend, and the paper-critical backend observations replicate on one additional MP-SPDZ
version. The contribution is in software testing; we introduce no new MPC protocol,
privacy theorem, or static-analysis technique.
\end{abstract}

\section{Introduction}
\label{sec:intro}
An MPC framework such as MP-SPDZ~\cite{keller2020mpspdz} compiles a program into a
protocol that several parties execute so each learns only its prescribed output.
Building a correct \emph{application} on top of such a framework is a separate task from
the framework's own security argument: an application author can, by accident or by an
injected fault, write source that reveals a value the functionality was meant to protect.
When such an application is wired into continuous integration (CI), a passing test suite
is easy to mistake for evidence that the privacy property holds. This paper is a case
study of \emph{what that test suite can and cannot establish}, told in the vocabulary of
software testing: test oracles, conformance tests, and mutation adequacy.

The subject computes, per recipient, whether releasing a query's output would let a
protected party's posterior belief exceed a public threshold, and---on accept---delivers
the output \emph{privately} to only the intended recipient. Two properties must be
tested: functional correctness of the accept/reject/mask decision, and the
\emph{delivery} discipline (only party $j$ learns $(\text{accept}_j,
\text{payload}_j)$). There is no reference implementation to serve as an oracle, and the
naive way to obtain one---feeding expected outputs into the harness---risks the classic
\emph{oracle-in-the-SUT} anti-pattern, where a test passes because the expected answer
leaked into the system under test.

\paragraph{Contributions}
The contribution is in software testing; we introduce no new MPC protocol, privacy
theorem, or static-analysis technique. We contribute:
\begin{enumerate}[leftmargin=1.4em,itemsep=2pt]
\item a \textbf{conformance-test design} for a subject with no trusted oracle
(\S\ref{sec:method});
\item an \textbf{anti-echo interface} that keeps expected outputs and post-state out of
the system under test (\S\ref{sec:method});
\item \textbf{layered functional, transcript, and evidence oracles}, each defeating a
distinct way a conformance test can be vacuous (\S\ref{sec:method});
\item a \textbf{mutation analysis} of the compiled-delivery checker with honest killed /
survived / stillborn accounting (\S\ref{sec:mutation});
\item a \textbf{pre-registered held-out mutation protocol} that reduces post-hoc
adaptation of a checker to the mutants used to harden it (\S\ref{sec:heldout}); and
\item \textbf{reproducible adequacy-boundary evidence}: the layers that miss a fault and
the ones that catch it, reproduced from a clean checkout (\S\ref{sec:repro},
\S\ref{sec:boundary}).
\end{enumerate}

\paragraph{Research questions}
We organize the evaluation around three questions, each mapped to existing results:
\begin{description}[leftmargin=1.1em,itemsep=1pt]
\item[RQ1] Which functional, delivery, transcript, and provenance fault classes are
detected by the layered test oracles?
\item[RQ2] Which pre-registered source-realizable held-out mutants survive the frozen
delivery checker, and which downstream oracle detects them?
\item[RQ3] Do the reported test outcomes reproduce from a clean checkout, and do the
paper-critical backend observations recur on the additional MP-SPDZ version?
\end{description}

\section{Subject and Fault Models}
\label{sec:background}

\paragraph{The subject under test}
Following PLAS 2012~\cite{plas2012}, $N$ parties hold secrets in a finite domain $D$;
each observer $j$ holds a belief over the others' secrets. For a query $Q$, the mechanism
checks, per recipient, whether releasing $Q$'s output would let any protected party's
posterior exceed a public threshold, quantifying over \emph{every possible output} so the
accept/reject decision is simulatable; on accept the recipient privately learns the
output, on reject a masked constant, and no party may learn another's verdict. We test
deterministic, total, public queries; two instantiate the subject: \code{p1\_is\_max} and
\code{sum\_even}.

\paragraph{Backend}
Circuits are compiled and run with MP-SPDZ pinned at commit \code{9d809599}, backend
\code{replicated-ring-party.x}: three-party replicated secret sharing over $\Ztfour$,
semi-honest, honest majority. The compiler emits a manifest of \emph{tapes} (a main tape
plus comparison subtapes). Two backend facts recur and matter for the checker under test.
First, a public reveal and a legitimate masked comparison-open are the \emph{same} opcode:
MP-SPDZ ``uses a single instruction for opening''~\cite{keller2020mpspdz}, and the
correctness-check flag does not change this. Second, in the compiled paths exercised here
we observed cross-tape transfer through memory and through register arguments passed by
\calltape{} (opcode \code{0xec}) and received by \callarg{} (opcode \code{0xed}); a direct
cross-tape register reference is a compiler error. We do \emph{not} claim these are the
only possible cross-tape channels.

\paragraph{Runtime protocol model (out of scope for the tests)}
A \emph{protocol-level} privacy argument would target a runtime adversary---at most one
semi-honest corrupted party among the three, honest majority, authenticated encrypted
channels, process isolation (stated, \emph{not} enforced by the single-host test
harness). Our functional and conformance tests do \emph{not} address it; that hand-off is
\S\ref{sec:boundary}.

\paragraph{Mutation model (the operator space of the study)}
The mutation study injects faults into the application \code{.mpc} source. Because that
source is compile-time Python, we state the operator space explicitly rather than
``source only.'' \emph{The mutation model permits only the application-level
computational and delivery transformations enumerated by the corpus. Arbitrary
compile-time Python imports, filesystem or network side effects, modification of the
compiler environment, and mutation of the oracle, checker, policy, CI workflow,
validator, or compiler are excluded.} This is the \emph{operator space} of the mutation
analysis (\S\ref{sec:mutation}), \emph{not} an adversarial-security boundary: it delimits
which transformations the study applies, and the oracle, checker, and compiler are the
trusted test infrastructure (Fig.~\ref{fig:arch}). We make no claim under collusion, a
malicious party, unencrypted channels, or a shared host, and no performance claim.

\section{Conformance-Test Design}
\label{sec:method}
Each layer defeats a specific way a conformance test can be vacuous. We state what each
layer \emph{operationally} provides, not that it is ``sound.''

\paragraph{A separately implemented pseudo-oracle}
The test oracle is a plaintext model written from the paper, separately from the circuit
and from the project's earlier exact-rational reference model, transcribing the
all-possible-outputs check directly: for each recipient it recomputes the posterior belief
conditioned on \emph{every} possible query output, accepts only if no protected party's
posterior exceeds the public threshold under any output, and delivers the actual output on
accept and a masked constant on reject---the decision the circuit must match. It is a
\emph{pseudo-oracle}~\cite{oracleproblem} (a
separate implementation of the same specification), \emph{not} an independently validated
ground truth: it shares the specification with the circuit, so a \emph{correlated}
misreading of PLAS could make both agree on the wrong behaviour. It did carry one fatal
transcription error (conditioning on the actual output only) until testing caught it. We
state this shared-specification / correlated-error risk wherever we rely on oracle
agreement (\S\ref{sec:threats}).

\paragraph{An anti-echo interface}
Before any circuit was written, the interface was fixed so that expected outputs and
expected post-state \emph{never enter the system under test}---neither compiled in nor
supplied as runtime inputs; they live only in the external harness, obtained from the
pseudo-oracle. Circuit inputs are exactly the public parameters and the secret-shared
secrets and beliefs, and the harness runs at least one state beyond the fixture, so a
constant-output circuit cannot pass by accident. Beliefs travel as dense unnormalized
non-negative integer weights; the threshold check avoids division ($b\,M \le a\,Z$).
Because MP-SPDZ comparison is signed, the no-wraparound requirement is $B < 2^{k-1}$ (not
the naive $2^k > B$), which we pin with a counterexample test.

\paragraph{A strict transcript oracle}
A correct party's captured stdout must be exactly its two own records; any foreign,
duplicate, unknown, missing, or extra line makes the test \emph{fail closed}. This is an
operational output-conformance oracle over the enumerated transcript cases on the
observed stdout channel; it observes selected output channels and does not establish
absence of every possible leak. It becomes the second line of defence in
\S\ref{sec:heldout}.

\paragraph{Recomputed, hash-bound test evidence}
Each run retains a typed record; in CI the validator requires each record's source hash
and delivery signature to equal values recomputed from the checked-out source and a fresh
compile, and binds each record to a canonical case via a recomputed input hash and
pseudo-oracle verdict. This establishes \emph{self-consistency and provenance} of the test
evidence \emph{under the trusted CI workflow}; it is not integrity against an actor who
can alter source, checker, workflow, and evidence together. It is the evidence-discipline
neighbour of reproducible builds~\cite{reprobuilds}, recomputed per test case rather than
attesting a whole artifact.

\subsection{Test artifact and results}
\label{sec:results}
On the fixture (two invocations: one all-accept, one with a per-recipient reject and
belief preservation) plus two further valid states, the circuit reproduces the
pseudo-oracle's visible outputs, payloads, and reconstructed weights. A \emph{bounded,
constructed} adversarial matrix of 228 cases (216 single-invocation $+$ 12 carried; all 27
secret tuples $\times$ two queries $\times$ uniform / non-uniform / per-party-scaled
integer weights near the bit bound) all match the pseudo-oracle. This is a constructed
test matrix, \emph{not} general coverage. The conformance package holds 92 collected
tests---46 functional and 46 delivery-checker tests---and 9 reference test functions (25
collected items), all green; \emph{test counts are not themselves a result}. Five
committed executable negative controls are rejected by the checker (\S\ref{sec:mutation}).
No timing is reported.

\section{Mutation Analysis of the Delivery Checker}
\label{sec:mutation}
Functional conformance says nothing about \emph{how} a value is delivered: a circuit can
compute correct verdicts and broadcast them. We therefore built a static
delivery-conformance checker that inspects the compiled tape manifest, and evaluated its
\emph{adequacy} by mutation analysis~\cite{demillo1978,jiaharman} over the operator space
of \S\ref{sec:background}. The first sequence is \emph{retrospective and adaptively
discovered}, not an independently designed operator set: the checker was repeatedly
hardened against the same mutants later used as evidence, so this sequence yields no
held-out adequacy estimate. \S\ref{sec:heldout} addresses that.

\paragraph{Mutant accounting}
One motivating transcript failure (\textbf{B0}); six compiled-delivery mutants
(\textbf{B1--B6}); one semantic mutant (\textbf{S1}). The six are not homogeneous: B1, B2,
B3 and B5 are committed executable \emph{source} mutants; \textbf{B4 is a synthetic
compiled-manifest counterexample, not a source \code{.mpc}}; and B6 is a reconstructed
source mutant whose naive realization is itself \emph{killed} (\S\ref{sec:b6}). B0:
changing \code{reveal\_to(j)} to a public \code{reveal()} while keeping the per-party print
compiles to a public open of every verdict, yet a stdout-only test reported success---which
motivated inspecting the \emph{compiled} delivery. B1--B3 and B5 each \emph{survived} the
then-current checker \emph{as committed source mutants}, and each was killed by adding one
detection rule, so the final rule set is the record of this progression: B1 (a separate
\code{@function\_tape} that reveals and prints) forced whole-manifest inspection rather than
main-tape-only; B2 (a name-spoofed subtape doing a wrong-player delivery and a file sink)
forced content rules---delivery players bound across \emph{all} tapes, no cleartext sinks,
and a strict masked-subtape name pattern; B3 (a \code{reveal(False)} of a verdict in a
duplicate \code{EQZ(3)\_63} via scalar memory) forced treating \code{False} opens as public
and pinning the exact comparison-subtape multiset; and B5 (the same via vectorized
\code{vstms}/\code{vldms}) forced broadening the memory rule to vectorized forms.
\textbf{B4} is the observation that the multiset rule is blind to tape
\emph{bodies}---a \code{reveal(False)} of the verdict placed in an \emph{existing}
\code{EQZ(3)\_63} body with the three pinned names intact---demonstrated with a
\emph{synthetic manifest}, not a compiled source mutant; against the final checker it is
killed by the subtape-memory rule. The clean build stores nothing in its main tape and
touches no memory in its subtapes, so forbidding memory is a restriction with no false
positives on the honest build.

\subsection{B6, at its exact strength}
\label{sec:b6}
We scope B6 precisely. We reconstructed a mutant that routes party~1's verdict through the
\calltape/\callarg{} register channel. Compiled against the pinned backend and checked by
the final checker, this mutant is \textbf{KILLED}: the added tape breaks the pinned
comparison-subtape multiset, and MP-SPDZ's call frame also spills through memory, tripping
the memory rules. So \textbf{B6 is not a demonstrated bypass of the final checker}; because
a direct cross-tape register reference is a compile error, the B3/B5 source mutants
therefore used an attacker-introduced memory hop, which the memory rules catch.

Its content is narrower. The \emph{honest} build passes secret comparison operands across
the tape boundary via \calltape{} (in main) received by \callarg{} in each of the three
comparison subtapes---no memory. Therefore a detection rule that forbade cross-tape
register-argument transfer of secrets, the way the memory rules close the memory channel,
would \textbf{reject the honest build}: the \callarg{} channel \emph{cannot be blocklisted
by opcode/channel identity} without a false positive on the honest build. Combined with the
opcode-identity fact, the testing lesson is precise: \textbf{this opcode-identity /
channel-blocklist checker cannot be promoted to a general non-leakage checker}.
Distinguishing legitimate from leaking flows requires analysis stronger than
opcode/channel identity---operand/provenance-sensitive dataflow, typing, a verified IR, or
other semantic machinery---\emph{which we did not evaluate} (\S\ref{sec:related}).

\subsection{S1: a semantic mutant the checker cannot see}
\label{sec:s1}
A mutant that drops the reject-mask (delivers the true output even to rejected recipients)
\textbf{survives} every delivery-checker rule---the delivery structure is intact---yet is
\textbf{killed by the pseudo-oracle}: on $\text{secrets}=(0,0,0)$, \code{p1\_is\_max}, the
true output is $1$ and all parties reject (oracle payload $0$), but S1 delivers $1$ to all
three. We ran this \textbf{end-to-end at the pinned backend}: all three parties complete
(return code $0$) and each delivers \code{ACCEPT 0 / PAYLOAD 1}, an executed oracle
mismatch at parties $[0,1,2]$. Delivery-conformance checks \emph{how} values are delivered,
not \emph{which}; only the functional pseudo-oracle, bounded by test coverage, constrains
that.

\section{A Pre-Registered, Held-Out Mutation Study}
\label{sec:heldout}
An adaptive sequence adapts to the tool it hardens. Freezing the checker and
pre-registering a temporally held-out corpus \emph{reduces} post-hoc adaptation, although
the study remains white-box and same-project rather than an independent red-team
evaluation. We committed a corpus of 22 mutants with locked predictions \emph{before}
running them, then ran once against the frozen checker; we report per-category outcomes and
\emph{no} aggregate mutation score.

\subsection{Mutation operators and the pre-registration protocol}
\label{sec:protocol}
The 22 mutants instantiate seven operator categories, drawn from three sources so the
corpus is not a renaming of B0--B6: security mutation-testing practice (systematic operator
families, and separating \emph{stillborn} and \emph{equivalent} mutants from killed
ones~\cite{jiaharman,just2014}); the information-flow observation that leakage is a dataflow
rather than opcode-identity property, which \emph{predicts} surviving value-routed and
permutation mutants (\S\ref{sec:related}); and MP-SPDZ backend mechanisms (the open family,
the \calltape/\callarg{} register channel, memory forms, sink opcodes, and the cross-tape
compile error). The categories are: (1) recipient/destination; (2) public/private open; (3)
subtape/topology; (4) secret-transfer/channel; (5) output/value-semantic; (6)
transcript/output-channel; and (7) evidence/provenance (which targets the \emph{separate}
evidence validator, not the delivery checker). Concretely, the corpus exercises forms the
adaptive sequence never used: indirect (\code{ldmsi}) and \code{gf2n} memory loads inside a
subtape, network (\code{writesocket}) and file (\code{writesharestofile}) sinks, and numeric
(\code{print\_int}) prints---all killed by the checker's rules---alongside a
register-argument open of a passed value in an existing masked subtape (the H-O3 probe),
which no rule fires on and which therefore survives at the manifest level.
Table~\ref{tab:operators} lists the operator categories, the transformation each applies, the
source/synthetic split, and the headline outcome per category.

The protocol is two-phase and its integrity is visible in the version history. First, the
corpus, the mutant sources or synthetic transforms, and a \emph{locked prediction} for
every mutant---predicted compile outcome, predicted checker verdict, source realizability,
and denominator membership---are committed \emph{before} the checker is run on them. Second,
the study is executed \emph{once} and the machine-readable results are committed separately.
We then classify each mutant honestly: \emph{killed} (checker rejects), \emph{survived}
(checker accepts), \emph{stillborn} (does not compile; never counted as a kill), and
\emph{benign/equivalent} (correctly not flagged). We record per mutant whether it is
\emph{source-realizable} (a compiled \code{.mpc}) or a \emph{synthetic manifest-level probe}
whose source realizability is unproven, and we report \textbf{no aggregate mutation score
over the synthetic probes}: a surviving probe shows only that no rule fires on that assembly
pattern, not that a source program can produce it (B6 shows the naive realization is killed).
All 22 outcomes matched their pre-registered predictions---evidence about the checker's
\emph{rules}, not about an independent adversary's ingenuity.

\subsection{The decisive surviving mutant (H-R2)}
\label{sec:hr2}
Among three pre-registered source-realizable recipient-structure mutants, the checker killed
H-R1 and H-R3 and \emph{survived} the multiset-preserving H-R2 permutation. H-R2 rotates the
delivery target so party $j$'s verdict is delivered to player $r=(j{+}1)\bmod N$ while the
per-party record label is unchanged:

\begin{lstlisting}
for j in range(N):
    r = (j + 1) % N
    print_ln_to(r, "PRIV %s ACCEPT %s", j,
                accept[j].reveal_to(r))
    print_ln_to(r, "PRIV %s PAYLOAD %s", j,
                payload[j].reveal_to(r))
\end{lstlisting}

\noindent The same permutation applies to both the ACCEPT and the PAYLOAD record.
Table~\ref{tab:hr2} shows why it survives the structural checker: the destination-player
multiset $[0,0,1,1,2,2]$---all the main-tape delivery rule inspects---is preserved, so the

recipient permutations in general; it kills \emph{this concrete labelled mutant}.

\section{Reproduction and Cross-Version Replication}
\label{sec:repro}
The frozen artifact reproduces from a fresh checkout with a fresh build of the pinned
MP-SPDZ backend: 117 collected \code{pytest} items (the 92 conformance items plus the 9
reference test functions, which expand to 25), the named-case harness $4/4$, the 228-case
matrix $228/228$, the recomputed evidence, and the B4/B6/S1 reproductions all reproduce, and
the normalized per-tape \code{manifest\_signature} values recompute to the archived values
\emph{at the pin}. We reproduce those \emph{normalized-assembly} signatures, \emph{not} raw
binaries or assembly byte-for-byte. Separately, the paper-critical backend observations
replicate on one further MP-SPDZ version, v0.4.3 (\code{26a60536}): the shared
open-instruction family, the honest \calltape/\callarg{} path, the B6 behaviour, and S1's
structural survival with an executed oracle mismatch all recur, with no compile/API or
semantic change in what we exercised. This is two versions, not a cross-version
compatibility or version-independence claim, and we do \emph{not} claim the compiled-assembly
signatures reproduce across versions: only one additional version, on one host, for the
probed observations, was tested. A one-command reproduction wrapper and machine-readable
results are in the supplementary artifact.

\subsection{Results summary by research question}
\label{sec:rqsummary}
\textbf{RQ1.} The layered oracles detect the gross delivery-fault classes the checker has
rules for---public opens, illicit sinks, disallowed memory, off-pin tapes (Table~\ref{tab:matrix},
and the ``rule fires'' rows of Table~\ref{tab:heldout})---and the pseudo-oracle detects
value/semantic faults the delivery checker cannot see (S1; H-V1--H-V3); the provenance
mutants (H-E1, H-E2) are rejected by the separate evidence validator. \textbf{RQ2.} Of three
pre-registered source-realizable recipient-structure mutants the checker kills H-R1 and H-R3
and \emph{survives} H-R2; H-R2 is detected downstream by the \emph{transcript oracle} for
that concrete labelled mutant (\S\ref{sec:hr2}); the semantic survivors H-V1--H-V3 are
detected by the \emph{pseudo-oracle}. \textbf{RQ3.} All reported outcomes reproduce from a
clean checkout at the pin, and the four paper-critical backend observations recur on the
additional MP-SPDZ version; we make no stronger cross-version claim.

\section{What the Test Suite Establishes}
\label{sec:boundary}
The assurance is a chain of partial checks, no one of them a privacy proof. The pinned
\emph{compiler} rejects one naive cross-tape transfer outright (a direct cross-tape register
reference is a compile error; the B3/B5 source mutants therefore used an attacker-introduced
memory hop). The \emph{delivery checker} kills gross structural and channel mutant classes,
including forms outside its design set (exercised as manifest-level probes, not executable
source mutants), yet H-R2 shows it survives a multiset-preserving wrong-recipient
\emph{structure}. The \emph{transcript oracle} killed that one concrete mutant; the
\emph{pseudo-oracle} kills semantic mutants delivery-checking survives; and \emph{evidence
recomputation} protects the consistency and provenance of these records under the trusted CI.
In the tested examples, later layers catch some faults earlier checks leave open; the layers
are complementary, not complete, and none, alone or together, is a protocol-level privacy
proof.

\paragraph{What would make it a guarantee}
Two verification obligations, neither supplied by our tests: (i) \emph{privacy of the
executed circuit}---a simulation argument or a formally-verified, dataflow-checked
comparison primitive; and (ii) \emph{semantic source-to-spec binding}---that the circuit
computes the intended function, not merely one that agrees with the pseudo-oracle on tested
cases (S1 shows why delivery privacy is insufficient without it). Our tests give
coverage-bounded evidence toward (ii) and nothing toward (i).

\section{Threats to Validity}
\label{sec:threats}
\begin{itemize}[leftmargin=1.2em,itemsep=1pt]
\item \textbf{Construct validity (mutation operator space).} The mutation study permits only
the enumerated application-level computational and delivery transformations; arbitrary
compile-time Python imports, filesystem or network side effects, compiler-environment
modification, and mutation of the oracle, checker, policy, CI, validator, or compiler are
excluded. Results are stated over this operator space, not an unrestricted adversary.
\item \textbf{Correlated authorship and AI assistance.} The implementation, tests, review
synthesis, and manuscript were produced within one project with substantial AI assistance;
model agreement is not independent validation.
\item \textbf{Adaptive overfitting, partially mitigated.} The checker was hardened against
the same mutants later used as the first evidence. Freezing the checker and pre-registering a
temporally held-out corpus (\S\ref{sec:heldout}) \emph{reduces} post-hoc adaptation, but the
study is white-box and same-project, not an independent red-team; we report per-category
outcomes rather than a mutation score.
\item \textbf{Pseudo-oracle pseudo-independence.} The oracle shares PLAS with the circuit; a
correlated spec misreading is possible. A cross-check against the project's exact reference
model is limited because that model implements a \emph{different} functionality; we state the
risk rather than claim it eliminated.
\item \textbf{External validity.} ``Conformance'' means agreement with a pseudo-oracle on
tested inputs. Results are for one deterministic-query functionality, $N{=}3$,
$D{=}\{0,1,2\}$, one backend, and a single-host harness that is not an adversarially isolated
deployment; the backend-level observations were additionally checked on one further MP-SPDZ
version, which is two versions, not a cross-version compatibility claim.
\item \textbf{No performance or simulation-security claim}; the boundary result is a
case-study observation, not a theorem.
\end{itemize}

\section{Related Work}
\label{sec:related}
Novelty statements below rest on a bounded, documented search; they are ``to the best of a
bounded search,'' not absolute.

\paragraph{Test oracles and pseudo-oracles}
The oracle problem---deciding the expected result of a test---is surveyed by Barr et
al.~\cite{oracleproblem}. When no ground truth exists, a pseudo-oracle (a second
implementation of the same specification) and metamorphic testing~\cite{metamorphic} are two
standard responses; both address oracle absence, but this study uses a separately implemented
pseudo-oracle rather than metamorphic relations across executions. Our anti-echo interface is
a discipline for avoiding the oracle-in-the-SUT trap; Wycheproof applies reference-oracle
conformance to crypto \emph{primitives} by feeding expected outputs, the opposite of our
anti-echo design.

\paragraph{Mutation testing and negative controls}
Mutation testing dates to DeMillo et al.~\cite{demillo1978} and is surveyed by Jia and
Harman~\cite{jiaharman}; whether mutants substitute for real faults is studied by Just et
al.~\cite{just2014}. We use mutants as an \emph{adequacy probe for a checker} and are careful
about mutant classes---killed, survived, stillborn (compile-invalid), and benign/equivalent
---never counting a stillborn mutant as a kill. Closest in spirit, MASC~\cite{masc} evaluates
crypto-misuse detectors with planted leaky mutants, but as an offline third-party-detector
benchmark rather than committed CI controls; and, unlike a standard mutation-score study, we
\emph{pre-register} a held-out corpus to reduce the adaptive coupling between a checker and
the mutants used to harden it.

\paragraph{Leakage is dataflow, not opcode identity}
ct-verif reduces constant-time to a 2-safety property on LLVM~IR~\cite{ctverif}; Binsec/Rel
decides constant-time \emph{relationally at the binary level} on operand
provenance~\cite{binsecrel}; Securify decides EVM-bytecode security on inferred
\emph{dataflow} facts rather than syntactic patterns~\cite{securify}. Our \S\ref{sec:b6}
instantiates this principle in the MPC-application testing setting; we claim the instantiation
and the pinned-backend mechanism, not the principle. The positive dual is language-based
security for MPC: Kerschbaum's information-flow type system~\cite{kerschbaum}, and, closest to
our finding, Skalka and Near's \emph{sound} static security-type system for a purpose-built
low-level MPC IR~\cite{skalkanear,skalkanear2}, which is sound \emph{because} its IR makes
declassification syntactically distinct---the property MP-SPDZ bytecode lacks. Reproducible
Builds~\cite{reprobuilds} is the evidence-discipline neighbour.

\section{Conclusion}
\label{sec:conclusion}
On one MP-SPDZ application, a separately implemented pseudo-oracle, an anti-echo interface, a
strict transcript oracle, and recomputed evidence give real, coverage-bounded,
operationally-stated test assurance and kill a family of gross delivery-fault classes---and
they have a sharp, nameable adequacy boundary. A static opcode-identity / channel-blocklist
checker cannot be promoted to a general non-leakage checker: a masked open and a raw reveal
are the same instruction, and the register channel a leak would use is the one the honest code
uses. A pre-registered, held-out mutation study makes the boundary concrete with a
\emph{surviving} source-realizable mutant (H-R2, a multiset-preserving mis-delivery) caught
only by a downstream oracle. Distinguishing the flows needs analysis stronger than
opcode/channel identity---which we did not evaluate---and a privacy guarantee needs a
protocol-level proof. Naming that boundary---and printing it next to the green check---is the
case study's point.
